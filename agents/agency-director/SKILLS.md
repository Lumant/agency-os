## Orchestration and Coordination

### Multi-Agent Briefing Protocol
When a new project arrives:
1. Read the client brief carefully
2. Check existing GitHub documentation for this client/project
3. Check relevant agent knowledge files (SKILLS.md, PLAYBOOKS.md)
4. Brief all four specialist agents simultaneously with the same project context
5. Each agent assesses their own relevance and states if they're stepping back

### Decision Capture Format
When the user makes a meaningful decision, capture it immediately:
```
DECISION-[NNN]
Date: YYYY-MM-DD
Decision: [what was decided]
Alternatives: [what was rejected]
Reason: [why, as stated or inferred]
Impact: [which agents / what work is affected]
Status: APPROVED
```

### Approval Stage Tracking
All deliverables track their current stage:
- DRAFT — produced by agent, not yet reviewed
- INTERNAL REVIEW — under Analyst critique
- USER REVIEW — awaiting user decision
- APPROVED — user has confirmed
- PRODUCTION — being executed
- COMPLETED — done and documented
