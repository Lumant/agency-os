# Agency Director — PLAYBOOKS.md

This file contains practical operating models and repeatable processes.

## Playbook 1: New Project Onboarding

**Trigger:** User brings a new project or client.

**Steps:**
1. Create `/projects/[client]/[project]/` folder in GitHub
2. Create PROJECT.md (what it is), BRIEF.md (scope and objectives), STATUS.md (initial: PLANNING), DECISIONS.md (empty), TODO.md (initial tasks), JOURNAL.md (entry 001)
3. Brief all four specialist agents with the brief
4. Collect each agent's initial assessment and planned contributions
5. Send user a summary of how the agency will approach the project
6. Set first night cycle tasks based on what can begin immediately

## Playbook 2: Nightly Cycle

**Trigger:** Evening, before 00:00 Helsinki time.

**Steps:**
1. Review what's pending across all active projects
2. Check what approvals are needed vs. what's cleared to execute
3. Assign specific tasks to each relevant agent for the night
4. Send **evening report** to user: per-project agent tasks + expected morning deliverables
5. Execute agent work, including Analyst challenge loop
6. Compile outputs
7. Send **morning report**: completed / key findings / decisions required / next step
8. Update JOURNAL.md and STATUS.md for all active projects

## Playbook 3: Analyst Challenge Loop

**Trigger:** Before any significant deliverable reaches USER REVIEW stage.

**Steps:**
1. Share draft deliverable with Analyst
2. Analyst reviews against the ten challenge questions (see Analyst ROLE.md)
3. Analyst sends specific critique to relevant agents
4. Agents revise or respond to critique
5. Director reviews final version
6. Move to USER REVIEW only after internal challenge is complete

## Playbook 4: User Decision Capture

**Trigger:** User makes any meaningful decision during conversation.

**Steps:**
1. Identify the decision (approval, rejection, preference, direction change)
2. Create a numbered DECISION record in the project's DECISIONS.md
3. Note the impact on each relevant agent
4. Update TODO.md and STATUS.md if the decision changes what's next
5. Brief relevant agents on the decision before their next task
